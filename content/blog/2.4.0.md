We're announcing the release of OpenFusionLauncher v2.4.0.
It hasn't been very long since the release of v2.3.x, but there are a handful of nifty improvements and a big new feature that we're excited to share:

## Self-Update

Packaged versions of the launcher (installed via either the Windows installer, Linux AppImage, or any MacOS build) can now update themselves whenever a launcher update is available.
This means you no longer have to uninstall the old version and go to the OpenFusion website to install a new one.

{{< figure
  src="images/2.4.0-self-update.png"
  alt="The new update notification toast, showing a new, green 'Update Now' button, along with the old website link button below it, now blue."
>}}

The update is downloaded within the launcher, and the launcher automatically restarts to apply it. It's a seamless experience that makes it easier for our users to pick up fixes and new features.
You can also opt-in to pre-release builds through the launcher settings page.
Users using the portable builds of the launcher will still get update notifications, but must update through the website as before.

## Game Builds Page Improvements

The game builds page no longer eats all of your CPU the minute you open it. Instead, you can validate builds by clicking the yellow "Validate" buttons next to each one you'd like to validate.
You can also hit the "Validate All" button to queue them all up in one sweep, as before.
Builds also show their size in the most relevant unit, instead of just GB.

{{< figure
  src="images/2.4.0-new-game-builds-page.png"
  alt="The new Game Builds page, showing a new, yellow 'Validate All' button near the top as well as individual yellow 'Validate' buttons at the right border of each build."
>}}

Manual game builds can now also specify a separate URI for the `main.unity3d` file. This is useful for builds that share an asset URL but have separate `main.unity3d` files.
If you do not specify the main file URI, the launcher will fall back to the default URI, rooted in the asset URI.

{{< figure
  src="images/2.4.0-new-manual-build-modal.png"
  alt="The new Add Build modal, showing a new 'Main Url (optional)' field below the 'Asset Url' field."
>}}

## Isolated In-Game Settings

Previously, FusionFall shared its in-game settings with all other Unity WebPlayer games on the system.
This caused all sorts of issues where vsync settings set by other games caused performance issues, particularly on the new 64-bit game engine.
This has now been remediated: the launcher now keeps its own copy of FusionFall's settings, so other games can no longer interfere with it.
The launcher also automatically strips out harmful settings that may have been left by other games.

## Other Improvements
- Protocol registration (and `.desktop` file creation on Linux) can now be disabled by putting `OFL_NO_REGISTRATION=1` in your environment.
- The MacOS DMG and Linux AppImage are now cryptographically signed, in addition to the signed executables and installer on Windows.
  - For MacOS users, this means no more having to go into your system settings to allow the launcher to run.
  - Linux users can validate the embedded AppImage signature using the [published public key](https://github.com/OpenFusionProject/OpenFusionLauncher/releases/download/2.4.0/linux-public-key.asc).
- The 64-bit webplayer now handles vsync, game object clone naming, and Alt-F4 in fullscreen mode the same way the 32-bit webplayer does.
- Fixed the 64-bit webplayer crashing during shutdown when closed in fullscreen mode.
- Fixed the offline cache incorrectly marking `main.unity3d` files as corrupt for game builds that do not store it under the same asset URI.
- Fixed smart quotes breaking launch profiles on MacOS.
