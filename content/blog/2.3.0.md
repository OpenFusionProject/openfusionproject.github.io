We're *very* excited to announce the latest release of OpenFusionLauncher: v2.3.0.
This is a big release with *lots* of improvements, both big and small.

## New 64-bit Engine
This release comes with a massive change: **a 64-bit port of the game engine to Unity 4.** This is a huge leap forward in modernizing FusionFall to run on today's hardware. It boasts an increase anywhere from **+50% to +100% FPS** (in our testing) as well as improved graphics, fewer crashes, and higher performance. It also allows assets to be fetched over HTTPS without a proxy, so the proxy server will not be started if 64-bit mode is selected.

Running the original 32-bit engine is a significant performance hurdle on macOS specifically, so this new engine makes the game much more playable on that platform. As such, we have removed warnings of macOS being severely limited on performance from the website and associated documentation.

Although the community has tested this new engine pretty thoroughly, you will likely run into brand-new bugs. Please feel free to report these bugs to us in our #tech-support channel on the [OpenFusion Discord](https://discord.gg/DYavckB).

If you'd like to switch back to the original 32-bit engine for whatever reason, you can choose it in the Game Settings page under the Web Player Architecture setting.

## Deep Linking
Certain special links (`ofl://...` or redirects like [this one](https://api.dexlabs.systems/ofl)) can now be opened with OpenFusionLauncher v2.3.0 or later. This makes it easier than ever for players to add servers to their server list. When these links are visited, the launcher will automatically pre-fill the server details in the Add Server modal, so players don't have to manually type in the details themselves.

If a player visits a link for a server that is already added, the launcher will ask the player if they want to launch that server. Players can even allow the launcher to automatically launch the server on future visits to the link:

{{< figure
  src="images/2.3.0-deep-linking.png"

This allows you to do all sorts of cool stuff, like adding browser bookmarks or desktop shortcuts to one-click launch the game.

### Single Instance Architecture
It's important to note that this deep linking functionality required a major behavioral change to the launcher: **you can now only have one copy of the launcher open at a time.** Attempting to open the launcher multiple times will now un-hide and focus the existing copy of the launcher. This still allows for multiple copies of the game to be launched at a time.

If you'd like to avoid having to re-open the launcher for each game session you'd like to launch, you can use the existing Launch Behavior setting in the Launcher Settings and set it to "Stay Open".

## Discord Rich Presence
Discord integration has finally arrived to OpenFusionLauncher! Whenever you launch the game through the launcher, Discord will now show others that you are playing OpenFusionLauncher and will also show how long your game session has been going on for.

If you are playing on an OFAPI-enabled OpenFusion server (such as Retrobution), others will also be able to see which server you're playing on. Thanks to deep linking, they will even be able to click the shown button to add that server to their launcher or even launch that server automatically if they already have it.

## Other Improvements
- All executables on Windows are now cryptographically signed.
- The version of the game runner and engine are now displayed in the About modal.
- The launcher now automatically captures game logs and crash dumps.
  - A button has been added to the About modal that will package them together to help diagnose problems.
  - If a game crash or abnormal exit is detected, the launcher will report the exit code in an error toast.
- Environment variables can now be expanded in custom launch profiles as `{MY_VARIABLE}`.
- Old game caches are now deleted by default to save disk space.
- Linux-specific improvements:
  - Mouse wheel stuttering in-game has been fixed.
  - Application metadata (.desktop file) for the launcher is now automatically generated and registered with the DE.
    - This fixes an issue where the window or taskbar icons may be missing on some systems.
    - If this metadata is pre-existing on the system, it will not be overwritten.
  - The native titlebar of the system is now used instead of the custom one.
- Compatibility layer improvements on non-Windows:
  - Preset launch profiles are now sorted in order of what we recommend using.
  - Newly available preset launch profiles are now added without having to reset game settings to default.
  - A more detailed error message is now shown if the launcher could not find any launch profiles.
  - Proton launch profiles no longer include hardcoded Steam environment variables.
    - The value of these are now dynamically set at launch time.
  - Proton launch profiles now use Steam Linux Runtime to launch the game.
    - This should fix some black screen launches on Linux and Steam Deck.
  - When a launch profile is deleted, it's corresponding Wine/Proton prefix is now also deleted, if it exists.
  - Resetting game settings to default will now delete the Wine/Proton prefix for every launch profile.
- General bug fixes:
  - The asset proxy server no longer breaks local asset builds (served over `file://`).
  - The asset proxy server no longer leaks proxies when multiple game sessions are launched.
  - Spaces in server names or descriptions no longer cut the name short (or, in some cases, break game launch).
- Minor visual tweaks to the UI, as well as a spooky surprise.
- Added a launcher setting to disable easter eggs.
- General performance improvements.
